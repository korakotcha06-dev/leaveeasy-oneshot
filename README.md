# LeaveEasy — ระบบขอลาออนไลน์

ระบบยื่นและอนุมัติใบลาของที่ทำงาน เขียนเป็นงานเรียน **ADT-RAISE Batch 2 · Module 2 (สัปดาห์ที่ 6–9)**
ตามใบสั่งงานในไฟล์ `leaveeasy-spec.md`

เส้นทางหลักของระบบ: **พนักงานยื่นใบลา → หัวหน้าพิจารณา → อนุมัติหรือไม่อนุมัติ → บันทึกผลไว้ให้เปิดดูย้อนหลังได้**

กลุ่มเป้าหมายตามสเปกคือที่ทำงานขนาด 20–100 คน ที่มีผู้อนุมัติ 1–3 คน

## ผู้ใช้ 3 บทบาท

ค่าที่เก็บจริงในช่อง `users/{uid}.role` เป็นรหัสอังกฤษเสมอ ส่วนคำไทยใช้แสดงบนหน้าจอเท่านั้น

| บทบาท | ค่าใน `role` | ทำอะไรได้ | ทำอะไรไม่ได้ |
|---|---|---|---|
| ผู้ขอลา | `employee` | ยื่นใบลา · ดูใบลาของตัวเอง · เขียนความเห็นในใบของตัวเอง · ลบใบของตัวเองที่ยัง `รอพิจารณา` | ดูใบลาของคนอื่น · เปลี่ยนสถานะ · แก้ประเภทการลา |
| ผู้อนุมัติ | `manager` | ดูใบลาทุกใบ · อนุมัติ / ไม่อนุมัติใบของคนอื่น · เขียนความเห็นได้ทุกใบ | พิจารณาใบที่ตัวเองยื่น · ลบใบของคนอื่น · แก้ประเภทการลา |
| ฝ่ายบุคคล | `hr` | ทุกอย่างที่ `manager` ทำได้ · เพิ่ม/แก้/ลบประเภทการลา | พิจารณาใบที่ตัวเองยื่น · ลบใบของคนอื่น |

**ทุกคนที่สมัครเข้ามาเป็น `employee` เสมอ** การเลื่อนเป็น `manager` หรือ `hr` ทำได้ทางเดียวคือ
แก้ค่า `role` ด้วยมือใน Firebase Console — ระบบไม่มีหน้าจอจัดการบทบาท (ดู `BACKLOG.md` ข้อ 4)

รายละเอียดสิทธิ์ทั้งหมดแบบช่องต่อช่องอยู่ใน **[ACL.md](ACL.md)** ซึ่งตรงกับ `firestore.rules`

## เทคโนโลยีที่ใช้

- HTML + CSS + JavaScript (ES modules) ล้วน ๆ · **ไม่มี framework และไม่มีขั้นตอน build**
- Firebase โหลดจาก CDN **ตรึงเวอร์ชันไว้ที่ `12.18.0`** ทุกไฟล์
- Firestore เป็นฐานข้อมูล · Firebase Authentication เป็นระบบล็อกอิน · Firebase Hosting เป็นที่วางเว็บ
- ไม่มีเซิร์ฟเวอร์ของเราเอง ไม่มี Cloud Functions — หน้าเว็บคุยกับ Firestore ตรง ๆ
- ด่านความปลอดภัยเดียวที่ข้ามไม่ได้คือ `firestore.rules`

## เริ่มใช้งานในเครื่อง

### 1. สิ่งที่ต้องมีก่อน

| อย่าง | หมายเหตุ |
|---|---|
| Node.js 18 ขึ้นไป | ชุดทดสอบใช้ `fetch` และ `node --test` ที่มากับ Node รุ่นใหม่ |
| Firebase CLI | `npm install -g firebase-tools` |
| Java | **Firestore emulator เขียนด้วย Java ไม่มี Java ก็เปิด emulator ไม่ได้** ดูข้อควรระวังด้านล่าง |

**ข้อควรระวังเรื่อง Java** — เครื่องนี้ลง Java ผ่าน Homebrew ซึ่งติดตั้งแบบ keg-only แปลว่า Homebrew
ไม่ได้เอา `java` ไปวางใน PATH ให้ พิมพ์ `java -version` เฉย ๆ จะหาไม่เจอ ทุกคำสั่งที่เปิด emulator
จึงต้องชี้ที่อยู่ของ Java เอง

```bash
PATH="/opt/homebrew/opt/openjdk/bin:$PATH" firebase emulators:start
```

**ไม่ต้องจำ** — npm script ใส่ให้แล้วทุกตัว เรียก `npm run emulators` ได้เลย

### 2. ติดตั้ง

```bash
npm install
npx playwright install chromium   # ทำครั้งเดียว ถ้าจะรันเทสหน้าจอ
```

### 3. เปิดเว็บ

มีสองทาง และ **สองทางนี้คุยกับฐานข้อมูลคนละก้อน**

| คำสั่ง | เปิดที่ | คุยกับฐานข้อมูล |
|---|---|---|
| `npm run emulators` | http://localhost:5050 | ฐานจำลองในเครื่อง (ปลอดภัย ลบทิ้งได้) |
| `npm run dev` | http://localhost:3000 | **ฐานข้อมูลจริงบน Firebase** |

> ### กฎพอร์ต 5050
> `js/firebase.js` ต่อฐานจำลอง **ก็ต่อเมื่อพอร์ตเป็น `5050` เป๊ะ ๆ เท่านั้น** พอร์ตอื่นทั้งหมด
> รวมถึง 3000 วิ่งไปหาฐานข้อมูลจริง
>
> ชุดทดสอบ **ล้างฐานข้อมูลทิ้งทั้งก้อน** ก่อนทุกเทส ถ้าไปรันที่พอร์ตอื่นเท่ากับสั่งลบข้อมูลจริง
> **ทดสอบทุกอย่างที่ 5050 เท่านั้น**

เปิด emulator ค้างไว้แล้วดูข้อมูลในฐานจำลองได้ที่ http://localhost:4000 (Emulator UI)

### 4. ใส่ข้อมูลตัวอย่าง

ข้อมูลตัวอย่างตามสเปกหัวข้อ 7 คือ ผู้ใช้ 3 คน · ประเภทการลา 3 แบบ · ใบลา 5 ใบ (รอพิจารณา 3 อนุมัติ 1
ไม่อนุมัติ 1) · ความเห็น 4 รายการ

**ในฐานจำลอง** — เปิด emulator ค้างไว้ แล้วสั่ง

```bash
node -e "require('./tests/fixtures').seedEmulator().then(r=>console.log('seed ok',r.counts))"
```

คำสั่งนี้ยิงผ่าน REST ของ emulator ด้วยสิทธิ์ผู้ดูแล ซึ่งข้าม `firestore.rules` ได้ตามการออกแบบ
พร้อมสร้างบัญชีทดสอบ 3 บทบาทให้ด้วย

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| `employee` | somchai@example.com | `test1234` |
| `manager` | somying@example.com | `test1234` |
| `hr` | somsri@example.com | `test1234` |

**ในฐานข้อมูลจริง** — ต้องใส่ผ่าน Firebase Console เท่านั้น

`seed.html` ที่อยู่ในโปรเจกต์ **ใช้ไม่ได้แล้วเมื่อกฎความปลอดภัยเปิดใช้งาน** และนั่นถูกต้องแล้ว
ไม่ใช่บั๊ก — เหตุผลเต็ม ๆ อยู่ใน `BACKLOG.md` ข้อ 3

### 5. เปิดปุ่มผู้ช่วย AI (ไม่บังคับ)

ปุ่ม "ให้ AI ช่วยจัดประเภทการลา" ในหน้ายื่นใบลาใหม่ เรียก OpenRouter ตรงจากเบราว์เซอร์

```bash
cp js/ai-config.example.js js/ai-config.js
# แล้วแก้ apiKey ในไฟล์ที่คัดลอกมา
```

`js/ai-config.js` ถูกกันไว้สองชั้น — อยู่ใน `.gitignore` จึง **ไม่ขึ้น git** และอยู่ในช่อง
`hosting.ignore` ของ `firebase.json` จึง **ไม่ถูกอัปขึ้นเว็บจริงด้วย** (ตรวจแล้วว่า
`/js/ai-config.js` บนเว็บตอบ HTTP 404)

ผลที่ตามมาโดยตั้งใจคือ **ปุ่ม AI ทำงานเฉพาะตอนเปิดเว็บในเครื่อง** ส่วนบนเว็บจริงจะขึ้นข้อความ
ภาษาไทยว่ายังไม่ได้ตั้งค่า AI แล้วให้เลือกประเภทการลาเอง ไม่ค้างและไม่มี error หลุดขึ้นหน้าจอ
(มีเทสคุมพฤติกรรมข้อนี้ไว้ 5 ข้อ) · เหตุผลเต็มอยู่ใน `BACKLOG.md` ข้อ 1

## รันชุดทดสอบ

มีสองชุด ทั้งสองชุดผ่านทั้งหมด ณ วันส่งมอบ

| ชุด | จำนวน | เครื่องมือ | คำสั่ง |
|---|---|---|---|
| เทสหน้าจอ (end-to-end) | **92 เทส** ใน `tests/e2e/` และ `tests/smoke.spec.js` | Playwright + Chromium | `npm run test:e2e` |
| เทสกฎความปลอดภัย | **112 ข้อยืนยัน** ใน `tests/rules/` | `@firebase/rules-unit-testing` + `node --test` | `npm run test:rules` |

ลำดับที่ใช้ได้จริงตั้งแต่ศูนย์

```bash
npm install
npx playwright install chromium
npm run emulators      # หน้าต่างที่ 1 เปิดค้างไว้
npm run test:e2e       # หน้าต่างที่ 2
# ปิดแล้วเปิด emulator ใหม่คั่นกลาง
npm run test:rules
```

**สองเรื่องที่ห้ามพลาด**

1. เทสหน้าจอต้องวิ่งที่ **พอร์ต 5050** เท่านั้น (`playwright.config.js` ตรึง `baseURL` ไว้แล้ว
   และ `signInAs()` ตรวจซ้ำอีกชั้น)
2. **ห้ามรัน `test:rules` ปนรอบเดียวกับ `test:e2e`** เพราะเครื่องมือทดสอบกฎจะ **อัปโหลดไฟล์กฎทับ
   และล้างฐานข้อมูล** ระหว่างรัน ให้ปิดแล้วเปิด emulator ใหม่คั่นกลางทุกครั้ง หรือรันเทสกฎบน
   พอร์ต firestore คนละพอร์ตไปเลย

อยากได้คำสั่งเดียวจบสำหรับตอนส่งงานหรือ CI ใช้ `npm run test:ci` (เปิด emulator รันเทส แล้วเก็บกวาดให้เอง)

**รายละเอียดทั้งหมด — วิธีเขียนเทสใหม่ · API ของ fixtures · การแก้ปัญหาที่เจอบ่อย — อยู่ใน
[tests/README.md](tests/README.md) ไม่เขียนซ้ำที่นี่**

## นำขึ้นออนไลน์

```bash
firebase deploy --only hosting            # อัปโหลดหน้าเว็บ
firebase deploy --only firestore:rules    # อัปโหลดกฎความปลอดภัย
```

ทั้งสองอย่างอัปแยกกัน **อัปหน้าเว็บอย่างเดียวแล้วลืมอัปกฎ คือการปล่อยเว็บใหม่ไว้หลังกฎเก่า**
`firebase.json` กันไฟล์ที่ไม่ควรขึ้นเว็บไว้แล้ว (`tests/`, `node_modules/`, ไฟล์ `.md`, `firestore.rules`,
`js/ai-config.example.js`)
